# Plan #5 — Shadowing + New Exercise Types + Mass Content — Design

> **Status:** approved shape (user, 2026-06-23); pending multi-agent review + impl plan.
> **Scope:** PT only. **No new audio generation** this round (shadowing reuses
> existing TTS; new exercise types are text-based). RU/RO/CS untouched.

## Goal

Deliver the postponed Plan #5 work, minus the 6-voice audio expansion:
1. **Shadowing mode** — record your voice (MediaRecorder) and compare it
   side-by-side with the existing model audio (self-assessment).
2. **Four new exercise types** — error correction, conjugation, matching,
   multiple choice.
3. **Mass content** — more exercises per block + the new types, generated by
   **parallel Claude Sonnet subagents** (one per block).
4. **Richer lessons** — implement `<VerbConjugation>` and add a vocabulary
   section to lesson MDX; regenerate the 36 lessons.

## Approach (locked)

**Code contract first (owned by me, TDD), then parallel content agents.** The
Zod schema + UI runners must exist before content can be generated, because
content is validated against the schema and the anti-bleed gate. Freezing the
contract first lets ~9 Sonnet agents generate content in parallel with no
rework. (Rejected: per-type vertical slices — slower, no parallelism; agents
writing UI — risks visual/behavioral inconsistency.)

## Architecture (existing, reused)

- **Schema:** `lib/data/zod-schemas.ts` — `ExerciseTypeEnum` + per-type
  `z.literal('...')` data schemas, combined in three discriminated unions
  (`ExerciseSchema`, `GeneratedExerciseSchema`, `LlmItemSchema`). Zod 4 quirk:
  `discriminatedUnion` has no `.extend()`; each union is rebuilt explicitly.
- **UI:** `components/cards/<Type>Card.tsx`, dispatched by `ex.type` in
  `ExerciseRunner.tsx` → `AnswerableCard`. Flashcards use a grade path; the
  rest call `onSubmit(correct: boolean)`.
- **Config:** `SCHEMA_VERSION` + `EXERCISES_PER_LESSON` records in
  `scripts/config.ts` (one entry per type).
- **Content:** `lib/data/languages/pt/blocks/bN.json` arrays.
- **Gate:** `scripts/lib/latin-guard.ts` wired into verify-content (hard error).

## Phase 1 — New exercise types + shadowing (code, TDD)

For each new type: data schema → add to the 3 unions → `SCHEMA_VERSION` +
`EXERCISES_PER_LESSON` → `Card` component → `AnswerableCard` dispatch → unit
tests for the scoring/normalization logic.

| Type | `data` shape | Card behavior / scoring |
|---|---|---|
| `error_correction` | `{ sentence, correct, explanationEs }` | Show sentence with a typical ES→PT error; user types the fix; score = normalized (trim/lowercase/punct) match to `correct`; reveal `explanationEs`. |
| `conjugation` | `{ infinitive, person, tense, answer, hintEs }` | Prompt "infinitivo — persona/tempo"; user types the form; normalized match to `answer`. |
| `matching` | `{ pairs: [{ left, right }] }` (3–6 pairs) | Tap-to-connect left↔right; score = all pairs correct (and per-pair feedback). |
| `multiple_choice` | `{ question, options[2–4], correctIndex, explanationEs }` | MC buttons; score = chosen index === correctIndex; reveal explanation. |
| `shadowing` | `{ text, es, audioRef? }` | Play model audio (reuse existing hash if present, else none); MediaRecorder record; play both back; self-rate pass/fail (no auto-scoring, no STT). |

`textsFor` (audio-collector) returns `[]` for all new types **except** shadowing,
which reuses an existing hash and never triggers new TTS. The anti-bleed
`findNonLatinDeep` already covers any new string field automatically.

Shadowing UX: graceful when `navigator.mediaDevices` is unavailable (permission
denied / unsupported) — show a clear message, fall back to listen-only.

## Phase 2 — Mass content (parallel Sonnet subagents)

Once Phase 1 merges (schema frozen), dispatch one Sonnet subagent per block
(b2–b10; b1 optional). Each agent, for **its** block only:
- Receives: block concepts + `vocabKey`, the frozen Zod data shapes with 2–3
  gold examples per type, the esContrast pedagogy rules, and the hard rule
  "Portuguese/Spanish only — no other writing systems."
- Generates **text-only** content (no audio): the 4 new types (~8–10 each) plus
  extra `translation` / `fill_blank` / `verb_preposition` (~15 total). Skips
  `flashcard`/`listening` (those need TTS — deferred).
- Writes to a per-block **staging file** (`blocks/bN.staged.json`) — no two
  agents touch the same file, so parallelism is conflict-free.

Merge step (me): validate each staged file against the schema + gate, assign
ids/`schemaVersion`, append into `bN.json`, then run `verify:content` (STRICT)
+ typecheck + tests + build. Reject/return-to-agent anything that fails.

## Phase 3 — Richer lessons

- Implement `<VerbConjugation verb tense />` MDX component (table; lookup in
  `FALLBACK_DICTIONARY`, fall back to a generated table) + register in
  `lessonMdxComponents`.
- Add a **Vocabulary** block to lesson MDX (the `vocabKey` words with ES gloss).
- Regenerate the 36 lessons (pipeline or agents) with the richer template; the
  anti-bleed gate already guards lesson writes.

## Testing

- Unit (vitest): scoring/normalization for each new type; schema round-trips;
  `latin-guard` already covers bleed.
- `verify:content` (STRICT) green after each content merge.
- `npm run build` + full suite green.
- Manual smoke: shadowing record/playback in a real browser (MediaRecorder).

## Decisions

- **Volume:** ~8–10 per new type + ~15 extra existing per block (adjustable).
- **No audio** for new content; shadowing reuses existing audio.
- **Content generator:** Claude Sonnet subagents (no bleed; higher quality than
  MiniMax-highspeed). The MiniMax pipeline + gate remain for audio-bearing
  regen later.

## Review resolutions (multi-agent review, 2026-06-23)

Two reviewers (devils-advocate + frontend-engineer) converged. Decisions:

**R1 — Audio-optional schema (was a blocker).** `RequiredGeneratedFields`
(`zod-schemas.ts:302`) makes `audio` required, and `verify-content` parses every
exercise with `GeneratedExerciseSchema` in STRICT mode → text-only types would
fail "audio required". Fix: the new types' `*Gen` schemas declare `audio`
**optional**; `AUDIO_REQUIRED` (verify-content) stays the single enforcement set
and is NOT extended to the new types. First task of Phase 1, before any Card.

**R2 — Content path = agents write JSON, a merge script assigns IDs.** Agents do
**not** go through `generate-content.ts`; they emit schema-shaped exercise
objects **without `id`** to `blocks/bN.staged.json`. A new `merge-staged.ts`
reuses the existing `contentId()` hashing, but checks the **global** id set and
fails loudly on any collision (8-char hash → ~2% collision risk across ~460 new
items; never silently drop). Therefore: no `TYPE_TO_TEMPLATE`/prompt files
needed for the new types, and **`schemaVersion` is a script cache concept, not a
data field** (the earlier draft wrongly said "assign schemaVersion at merge" —
removed).

**R3 — Answer contract.** `error_correction`, `conjugation`, `multiple_choice`
fit `onSubmit(answer, correct)` + the standard 4-button `GradePanel` cleanly.
`matching` serializes its final state as `answer = JSON.stringify(pairs)` and
reports `correct = allPairsRight`. `shadowing` keeps an internal state machine
(idle→play-model→record→playback→reveal) and, after the user reveals, uses the
**standard 4-button GradePanel** as the self-rating (not pass/fail — the FSRS
rating IS the self-assessment). No runner contract change beyond adding two
dispatch branches in `AnswerableCard`.

**R4 — Per-type wiring checklist (every new type touches ~12 surfaces).** Each
of the 5 types must update: `ExerciseTypeEnum`; the per-type `*Data`/`*Override`/
`*Ex`/`*Gen` schemas; the 3 discriminated unions; `ExerciseDataByTypeSchema`;
`VariantOverrideByTypeSchema`; the `LlmItem` omit list; `TYPE_TO_TEMPLATE` (→
`null`); `AUDIO_REQUIRED` (exclude); `SCHEMA_VERSION`; `EXERCISES_PER_LESSON`;
`textsFor()` (→ `[]`, except shadowing); `AnswerableCard` dispatch + the Card.
The impl plan enumerates these as an explicit per-type checklist.

**R5 — ShadowingCard / MediaRecorder specifics.** Detect MIME via
`['audio/webm;codecs=opus','audio/mp4','audio/ogg'].find(MediaRecorder.isTypeSupported)`
(iOS Safari only supports `audio/mp4`). **Stop the model `<audio>` before
`MediaRecorder.start()`** (iOS audio-session conflict). Keep the `MediaStream` in
a `useRef` and stop all tracks in the `useEffect` cleanup (React 19 Strict-Mode
double-mount). Playback is **sequential** (model then recording) for the MVP;
`URL.createObjectURL(blob)` is revoked on re-record/unmount. Requires HTTPS or
`localhost`. `audioRef` may be absent → record-only (no model playback). Manual
smoke on a real iPhone is a Phase-1 exit criterion.

**R6 — FSRS new-card flood.** ~460 new exercises will appear as "new" cards.
Before mass content lands, verify the daily-review query rate-limits new-card
introduction; if it does not, add a cap so existing learners aren't flooded.

**R7 — VerbConjugation + vocab section are data-driven, not dictionary lookups.**
`fallback-dictionary.ts` is `Record<word, esGloss>` — it has no conjugation
tables. So `<VerbConjugation verb tense forms={[...6 forms...]} />` renders a
table from **props the lesson MDX supplies** (the generator emits the 6 forms;
the anti-bleed gate covers them). The vocabulary section is **static MDX** (the
generator writes the `vocabKey` words + ES gloss as MDX), not a runtime
component. Both register in `lessonMdxComponents` only as far as
`VerbConjugation` needs (a presentational client component; the ~3KB dict is not
imported). Keeps Phase 3 light.

**R8 — Content quality rubric (merge review).** Schema + gate conformance does
not guarantee pedagogy. At merge, human-review samples per block against a
rubric: `esContrast`/`explanationEs` must name the **specific** Spanish
interference pattern; `error_correction` sentences must contain an error a
Spanish speaker would actually make; `conjugation.tense` must use a canonical
closed vocabulary (defined in the agent brief) matching what `<VerbConjugation>`
displays.

**R9 — Answer normalization.** `error_correction`/`conjugation` matching is
`trim` + `toLowerCase` + NFC, **accents significant** (getting `estão` vs `estao`
right is the point). Matches the existing `FillBlankCard`/`TranslationCard`
behavior; no accent-insensitivity.

**R10 — `multiple_choice` shares the options-grid with `ListeningCard`.** Extract
the shared "options grid → onSubmit(opt, opt===answer)" into a small shared piece
rather than copy-pasting; keep schemas separate (`ListeningData.audioText` vs
`multiple_choice` has none).

## Expert review resolutions (linguist + pedagogue, 2026-06-23)

A contrastive linguist and an SLA/pedagogy expert reviewed the whole corpus +
this design. Resolutions (audio-free unless flagged):

**E1 — PT-PT variant is unreachable (critical, code).** Legacy `ptOverrides`
(European text) were migrated under `variantOverrides["pt-br"]`
(`lib/data/variant.ts`), but `resolveExerciseData` only falls back to that key
for the legacy `"pt"` alias (`isLegacyPtAlias`, `exercise-resolver.ts:59-65`).
Net: `pt-pt` users get BR base; `pt-br` users get European overrides applied.
`variantOverrides` is part of the content-id hash, so **renaming keys in the
JSON would churn ids and orphan Dexie progress** → fix at the **resolver**:
`pt-pt` → `variantOverrides["pt-pt"] ?? variantOverrides["pt-br"]` (legacy
European); `pt-br`/`br` → no legacy override. Also fix
`ptOverridesToVariantOverrides` to emit `"pt-pt"` going forward, and `textsFor`'s
matching comment. Lives in the **content-fixes plan**, before 5b.

**E2 — Gate misses English/Spanish bleed (critical).** `latin-guard` only blocks
non-Latin scripts; surviving English (`"Eu the dei"`→lhe, `"Ela gave"`,
story `"announcing"`, `"sweatshirt"`) and mixed ES/PT sources pass. **Extend the
gate before 5b** with (a) an English-stopword heuristic over PT/ES fields and
(b) a structural check (fill_blank: blank count == answer count). Wire into
verify-content as errors. Content-fixes plan.

**E3 — Broken diagnostic items (content).** `diagnostic.json`: `q03b01` two
correct (mão+pão nasal), `q10b02` "pães" duplicated, `q08b01` no correct answer
(h silent in all four), `q19` marks valid BR `"Tem muitos livros"` wrong +
`conceptId` mismatch (`b3-ha-tem` vs `b3-existenciais`), `q06` mis-tagged
(ll→v). Fix in content-fixes plan.

**E4 — esContrast / MDX factual errors (content).** `ll→lh` is wrong — ES `ll`
→ PT **`ch`** (chave, chamar); fix `b1/l3-correspondencias.mdx` + the
`b1-corresp-ll-lh` concept tag. `"ligación"` is not Spanish → reframe as the
`ligar` false friend (PT telefonar/encender vs ES flirtear/atar). `"acalentar"`
misuse → `aquecer = calentar`. `"-ma siempre masculino"` is false (a cama, a
forma) → qualify to Greek-origin cultismos. Make all `esContrast` Spanish
(some are PT) and backfill empties on the false-friend/regência items.
Add missing classic false friends (embaraçada, esquisito, oficina, apenas,
salada). Content-fixes plan.

**E5 — Malformed exercises (content).** `b4.json` has a `verb_preposition` with
two blanks but one answer and the infinitive left in the sentence, and a
`translation` with a mixed ES/PT `source`. Fix/remove. Content-fixes plan.

**E6 — Interleaving is designed but not implemented (pedagogy, code).**
`buildDueQueue` (review-queue.ts) is recency-blocked and the `/learn` daily-mix
button routes to a single lesson. Real concept/type interleaving is the biggest
unused retention lever. Logic-only fix. → **Plan 5d (SRS/engagement)**, not
content.

**E7 — Lessons too thin → build the deferred richer lessons (pedagogy).** The
five consecutive verb blocks (B3–B7) ship without a single conjugation table;
hard contrastive lessons (b4/l4 perfeito↔imperfeito, b8/l3 colocação) get the
same 1-paragraph treatment. The deferred `<VerbConjugation>` + contrastive
tables + vocab section are a **real gap, not YAGNI — promote to build** (Plan
5c). Data-driven per R7.

**E8 — Exercise-type re-weighting (pedagogy → changes 5b).** The mix is
recognition-heavy. **`multiple_choice` is redundant** (it is the diagnostic
style; recognition already over-served) → **cap ≤3/block**, reserved for
discrimination items (gender/plural irregulars). **`matching` is low-value** for
adults (cognate pairing is trivial) → minimize or drop. Shift that budget to
**`error_correction` (highest value) + `conjugation` (fills production gap)**.
5b's "~8–10 each uniformly" is replaced by this weighting.

**E9 — Conjugation must be variant-aware + canonical vocab (5a/5b).**
`tense`/`person` are free strings; the answer (`falas` vs `fala`) depends on
tu/você → freeze a **closed canonical set** of ~12 `tense` labels and the
`person` set, and make conjugation answers variant-aware (or carry
variantOverrides). Defined in the agent brief (5b) and honored by the
`ConjugationCard`/`<VerbConjugation>` (5a/5c).

**E10 — merge validation (5b).** `merge-staged` must reject MC items with
duplicate options or out-of-range `correctIndex`, and error_correction items
whose `correct` is not the single uncontroversial fix.

**E11 — Shadowing self-eval (5a/5c).** Without STT, replace binary pass/fail
with 2–3 **feature-targeted** self-checks tied to the sentence's PT difficulty
("¿nasalizaste *pão*?", "¿la *r* inicial sonó como /h/?"), a repetition count,
and drive shadowing primarily from B1 minimal-pair/nasal/r/s-final content where
self-diagnosis by ear is feasible. Refines the 5a `ShadowingCard`.

**E12 — SRS/engagement fixes (pedagogy, code) → Plan 5d.** New-card floor on
heavy-review days (currently drops to 0 when reviews ≥ cap); lower
`leech_lapses_threshold` 8→4–5; **decouple XP from the FSRS rating** (Easy +5 >
Good +1 incentivizes mis-rating, corrupting the scheduler).

**E13 — Diagnostic ceiling items (pedagogy/content).** Diagnostic only covers
B1–B3, so prior learners can't place past B3. Add MCQ ceiling items from
B4/B6/B8 (no audio). Content-fixes plan.

**Deferred (need new audio, out of this round):** story `b3-s1` BR uses
`ementa` (should be `cardápio`); stories `b9-s2`/`b2-s2` English words in
audio-bearing text; `b10` flashcard `back` with `gave`.

### Plan map after review
